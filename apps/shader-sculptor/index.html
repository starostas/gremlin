Why this fits the GPU
CHECKING
Resolution and layer count are independent. Larger images get a longer search budget, capped at two minutes for up to 2,048 layers and six minutes for the larger layer options. Previews are limited to 512 pixels per side; the final image uses full resolution.
Every round tests 4,096 possible additions at the selected pixel resolution. Pixels outside each shape’s bounds are skipped because they cannot change its score. The target and current painting stay on the GPU. Pixel errors are reduced there; only candidate scores and occasional previews come back.
What is being discovered?
A bounded, layered drawing program. Geometry, color, opacity, and layer order are selected from pixel observations using greedy search. This is image approximation in a small graphics language, not unconstrained invention of a shader algorithm.
The app has a specialized CUDA evaluator for that language. It exports an equivalent integer Gremlin pixel program, checks sampled export pixels, and checks every final GPU pixel against a separate renderer. Working-buffer memory excludes the CUDA context.
Search time includes GPU initialization, scoring, proposal generation, reference checks, and preview output. Final source validation, SSH launch, and browser animation add some time. Recorded playback retains actual measured timings.

# D6: versioned import and an external libFuzzer adapter

Select LLVM 18 libFuzzer, supplied by Clang/compiler-rt, under Apache-2.0 with LLVM exception. The external tool performs all mutation and corpus evolution; gremlin does not implement a fuzzer. Its C++ harness supports the declared integer input transport and invokes gremlin's isolated oracle bridge for every valid input. The original ELF is never loaded in the fuzzer host. Target coverage is unavailable for uninstrumented ELF execution; any libFuzzer coverage is explicitly harness coverage, not target coverage. Candidate mismatches are preserved before signaling a finding to libFuzzer. Oracle failures are campaign infrastructure failures.

Define version-1 import JSON with the declared signature and cases `{input:[exact-width hex], expected:optional hex, provenance:[strings]}`. Imported labels are never accepted without fresh oracle replay; conflicting labels abort the import. Deduplicate canonical inputs, retain all provenance plus origin file hashes, and atomically publish a new output corpus/provenance pair only after successful replay. Existing corpora are also replayed when merging. Search's optional `corpus.initial_corpus` reads the resulting canonical corpus and replays it on a new run; checkpoints retain the actual observations thereafter.

Campaign interface: create/start/stop/poll/export. Creation compiles a concrete libFuzzer harness and records selected compiler/runtime and executable hashes, flags, target/configuration, input schema, seed, run/time budgets and coverage limitations. Start uses a separate supervisor process; poll and stop verify process identity before acting. A campaign is single-use; create a fresh campaign to rerun it. Export converts persisted, oracle-observed cases into the vendor-neutral import format. Campaign control and corpus import remain independent of search. No target-coverage or equivalence claim is inferred from running a fuzzer.

References: https://llvm.org/docs/LibFuzzer.html and https://llvm.org/docs/DeveloperPolicy.html#license .

Implemented commands:

```sh
gremlin import --config target.toml --input external-v1.json --output imported
# Optional merge: --corpus previous/corpus.json
# New searches can set corpus.initial_corpus = "imported/corpus.json".
gremlin campaign create --tool libfuzzer --config target.toml --compiler /usr/bin/clang++-18 --seed 1 --runs 100 --seconds 10 --output campaign --candidate wrong.gremlin
gremlin campaign start --directory campaign
gremlin campaign poll --directory campaign
gremlin campaign stop --directory campaign
gremlin campaign export --directory campaign --output external-v1.json
```

All candidate/configuration/tool identities are snapshotted. Background supervisor and fuzzer process identities include PID start times and executable hashes. A stopped or completed campaign cannot be restarted. The supervisor enforces a wall deadline in addition to libFuzzer's run/time/RSS controls. Every valid input uses the versioned little-endian integer transport and goes through the isolated binary oracle (or explicit development fixture). No target is loaded by the fuzzer harness. Case observations and candidate mismatches are persisted before the harness signals a finding; oracle failures use a separate campaign failure status.

Measured gates: duplicate import, wrong/corrupt input/labels, schema rejection, provenance union, imported inputs reaching synthesis, actual libFuzzer create/start/poll/stop/export/import, unavailable tool, and single-use campaign behavior all passed. The actual affine ELF campaign in `runs/fuzz-affine-wrong/` found a candidate mismatch (libFuzzer exit 77), preserved it, exported version-1 JSON and replayed it into `runs/fuzz-affine-imported/`. These are differential observations, not an evidence-level upgrade or target-coverage claim. Import output is published as a new directory after replay; existing output is never overwritten.

# D5: LLVM lowering and isolated artifact validation

Route: emit LLVM 18 textual IR, compile it with an explicitly selected Clang 18 executable, and record compiler hash/version, exact flags, source/IR/ELF hashes, compilation time and artifact size. No Rust LLVM binding or MLIR dependency. Default CPU builds do not invoke a compiler.

Lower validated CFGs without calls to an internal pure function returning `{value,status}`. Integer operations have no nsw/nuw/exact assumptions. Every instruction and terminator charges the gremlin step budget. Edge argument loads precede all destination stores, preserving simultaneous bindings; LLVM optimization can promote stack slots. Guard division zero and signed MIN/-1 before LLVM division/remainder. Reduce shifts modulo width; rotate complementary shifts are also reduced, preventing poison for zero shifts. Select operands are evaluated eagerly in source instruction order before selection. Loops preserve the explicit step budget.

Export `gremlin_target` under the declared integer ABI; it returns completed values and executes llvm.trap for noncompletion. Export a pure `gremlin_status` with the same inputs and u8 return for validation (0 completed, 1 division zero, 2 signed overflow, 3 step exhaustion). Both wrappers evaluate the same internal lowered function. The status probe allows precise trap/timeout classification without changing the strict binary oracle's treatment of arbitrary crashes. No target function is loaded in the host. Status and value exports are independently observed with the existing isolated deterministic binary oracle. Conformance tests also check that the target wrapper traps for noncompletion.

The compile command requires an explicit minimum candidate level E1/E2/E4. Re-evaluate the selected candidate against fresh oracle-labeled corpus inputs, supplied additional corpus inputs (including retained counterexamples), and configured independent holdouts before compilation. E4 additionally requires current binary-scoped equivalence for the exact candidate and target. The source hash is fixed before lowering. Artifact evidence remains TESTED at its measured level and never inherits the candidate's formal proof. Validate the compiled result against both CPU interpretation and the original binary/fixture observations, recording every observation and each identity. Compiler errors, resource failures and mismatches abort success. Calls are explicitly unsupported by this lowering gate.

Reference: https://releases.llvm.org/18.1.8/docs/LangRef.html .

Validation passed: all supported operators over every signed/unsigned integer width, zero and width-sized shifts/rotations, division zero/MIN overflow, eager trapping selection, CFG swapping through simultaneous edges, conditional/infinite loops, exact step-budget boundaries, missing compiler, compiler wall timeout, missing evidence request, and a bad candidate rejected before any LLVM/artifact output. Source is snapshotted once before gating. Refined configurations require `--corpus` so retained counterexamples are replayed rather than lost.

An actual affine ELF/candidate pair passed a fresh binary E4 gate, then compiled through Clang 18.1.3 at O2. Its artifact passed all corpus and fresh holdout checks against both the CPU interpreter and original isolated binary. The checked-in measurement is `docs/measurements/native-affine.json`; complete local observations/IR/ELF are in `runs/native-affine/`.

```sh
cargo run --release -p gremlin-cli -- compile --config runs/formal-example/affine.toml --candidate runs/formal-example/candidate.gremlin --min-evidence E4 --compiler /usr/bin/clang-18 --solver /usr/bin/z3 --timeout-ms 30000 --output runs/native-affine
```

For E1/E2 use that explicit minimum and omit `--solver`; use `--corpus RUN/corpus.json` to include retained counterexamples. The output directory must be new. Artifact evidence is measured E1/E2 and remains TESTED even when the candidate gate was E4. Native timing records include sandbox startup and repeated observations, and are not intrinsic function latency or a speedup claim. The emitted target retains the configured semantic step budget; it is a bounded replacement, not an unbounded loop-execution claim. Calls remain unsupported.

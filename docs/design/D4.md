# D4: complete straight-line binary models

Use pinned `iced-x86 = 1.21.0` (MIT) for decoding and the existing `object = 0.36.7` ELF reader. Neither defines gremlin semantics. Use the installed Z3 executable through SMT-LIB2 bit vectors with explicit solver and parent wall deadlines; record its version and hash. CPU-only build does not require Z3 at build time.

Initial binary subset: ELF64 x86-64 ET_DYN, an explicitly exported nonempty symbol, no initializers, dependencies or relocations. Decode the entire symbol, ending in a single near return. Accept register/immediate MOV, ADD, SUB, IMUL, XOR, AND, OR, NOT, NEG, and register address LEA, with 32/64-bit destinations in caller-saved general registers. A 32-bit write zero-extends. LEA is address arithmetic, never a memory access. Reject branches, calls, division, loads/stores, stack adjustments, flag consumers, callee-saved register writes and reads of undefined registers. Flags are unobservable because no accepted instruction consumes them. RET assumes a valid ABI caller return address. No implicit unconstrained register values. Constructors and writable executable segments are excluded because they could invalidate the decoded bytes. A separate concrete model replays counterexamples against the isolated original binary.

Candidate model: validated single-block gremlin IR with fixed-width bit vectors, eager instruction evaluation, wrapping arithmetic, modulo-width shifts/rotates, signed comparisons/division and explicit division traps. Record whether each instruction can trap; ask for an input where completion/trap behavior or completed output differs. Unsupported control flow/calls produce Unsupported. Straight-line instruction count supplies a complete execution bound, so successful binary-subset equivalence may receive binary E4 subject to the stated model and ABI assumptions. Reference-model comparison remains explicitly reference-model scope and cannot claim binary E4.

Proof reports bind candidate, binary, symbol bytes/address/size, ABI, lifter and solver identities, assumptions, query hash, status and replay observations. Outcomes are Equivalent, Counterexample, Timeout, Unsupported or Unknown. Infrastructure/protocol errors abort; an inconsistent concrete replay is a modeling error. Solver absence is not equivalence. SAT replay must reproduce the same difference on both concrete evaluators and the original isolated oracle before returning a trusted counterexample.

References: https://docs.rs/iced-x86/1.21.0/iced_x86/ and https://microsoft.github.io/z3guide/docs/theories/Bitvectors/ .

Validation completed with Z3 4.8.12: equivalent/inequivalent binary fixtures; original isolated oracle replay; all-width wrapping/modulo-shift and eager-trap reference checks; first-trap reason preservation; 32-bit destination zero extension; unsupported memory/calls/branches/callee-saved registers/undefined registers/prefixed returns and ELF initializers; solver Unknown, external Timeout, unavailable executable, and negative binary/reference scope tests. Symbol bytes are checked against executable PT_LOAD mapping; only ordinary unambiguous STT_FUNC exports are accepted. Dynamic metadata is restricted to hash/string/symbol tables and SONAME (no version/resolver/initializer/relocation behavior). The target must have a single-byte near RET. Address-size overrides are unsupported. Caller-saved arithmetic leaves only the integer return observable under the declared contract.

Reproduce an actual compiled affine binary proof:

```sh
python3 examples/build_formal.py
cargo run --release -p gremlin-cli -- verify --config runs/formal-example/affine.toml --candidate runs/formal-example/candidate.gremlin --solver /usr/bin/z3 --timeout-ms 10000 --output runs/formal-example/affine-proof.json
cargo run --release -p gremlin-cli -- verify --config runs/formal-example/affine.toml --candidate runs/formal-example/wrong.gremlin --solver /usr/bin/z3 --timeout-ms 10000 --output runs/formal-example/affine-counterexample.json
```

The first command returns binary `Equivalent`/E4; the wrong candidate returns exit 6 and a replayed `Counterexample`. `verify-reference --reference SOURCE --candidate SOURCE --solver PATH --timeout-ms N --output JSON` produces only reference-model scope. Reports include the full SMT query and its hash; checked-in measured reports are under `docs/measurements/`. Output files are never overwritten. The example compiler explicitly disables CET instrumentation to stay inside the declared instruction subset; arbitrary compiler output may correctly be Unsupported.

# D3: CUDA evaluation

Dependency choices: optional `gremlin-cuda` crate with a `cuda` Cargo feature, NVCC-compiled CUDA C++ kernel, and CUDA static runtime. No CUDA headers, libraries, tools, or driver are needed for feature-disabled CPU builds. NVCC is discovered from CUDA_HOME (default /usr/local/cuda); actual compiler, runtime, driver, and device identities are recorded. This uses the installed CUDA toolkit rather than adding a Rust CUDA abstraction dependency.

Execution: one warp per program and one lane per input, with a second grid dimension tiling input sets larger than 32. Each program is compiled from validated canonical CFG IR into a typed transport; it retains instruction/terminator budgets, simultaneous edge binding, traps, modulo shifts, and width-masked signed patterns. Register and edge-scratch memory are bounded by a caller memory budget and allocated in batches. Calls are explicitly unsupported by this backend; they remain a CPU module feature. No program is silently rerouted to different semantics.

A CLI worker with an external wall watchdog wraps native GPU calls. Kernel loops additionally obey the semantic step budget. Infrastructure, driver, compilation, and memory failures are run errors. CPU and GPU search must consume identical RNG streams and rank exactly the same fitness; timing is telemetry only.

Validation host supplied by user: NVIDIA RTX A4000 (16 GB), driver 590.48.01, CUDA toolkit 13.0.88. Rust 1.90.0 was installed in the remote account for testing. Transfer only source/manifests/tests, never local tokens or run credentials. Required GPU CI must fail explicitly if the feature/device is absent. Gate: >=10,000 seeded programs, all integer widths/operators, divergent CFGs, traps/timeouts, and corpus sizes 1/31/32/33/65. Measure marshalling/setup/transfers/kernel and end-to-end synthesis; do not infer acceleration from kernel time.

Implemented interface: build `cargo build --release -p gremlin-cli --features cuda`, then opt in with `[search.cuda]`, `memory_budget_mb = 1024`, and `wall_timeout_ms = 30000`. CPU is the default. Each population batch runs in a separate CUDA worker; the parent enforces a wall deadline and kills a stalled worker. The worker validates normalized IR, signature, input encodings and total device allocation before launch. Oversized batches fail with their required bytes; they are not silently truncated. Calls remain explicitly unsupported. Search generation/selection RNG order and stable fitness ordering are unchanged. Resume recalculates stored fitness on CPU. `cuda-batches.jsonl` records per-batch device, driver/runtime/compiler identity, allocation bytes, setup, transfer, kernel, host and worker wall times; the final integrity manifest covers it.

Measured on the supplied RTX A4000 (compute capability 8.6), CUDA runtime 13.0 / driver 13.1, NVCC 13.0.88:

- 10,000 seeded programs, all eight integer types, valid operators, divergent CFGs and loops, case counts 1/31/32/33/65, and budgets 0/1/64: **4,860,000 exact outcome/step comparisons passed**.
- Across 120 batches: setup 99.53 ms, transfer/allocation 159.25 ms, kernel 13.35 ms, total host evaluator 947.54 ms. CPU evaluation plus comparison took 980.28 ms. Aggregate evaluator throughput was 5.13 million candidate-cases/second on CUDA and 4.96 million on the CPU comparison path; the latter includes assertion overhead and is not a controlled speedup comparison.
- Full composed-u64 synthesis with seed 1: CPU 0.948 seconds, CUDA 4.263 seconds, both generation 10 / 639,416 candidate-case executions, identical complete search states and E2 candidate. Fresh worker/context initialization and transport make CUDA slower for this workload. No end-to-end acceleration claim.
- CUDA synthesis resume, 1 ms watchdog, 1 MiB memory rejection, and hidden-device error tests passed. Infrastructure failures record no evidence level.

Raw parity timings and compact synthesis measurements are checked in under `docs/measurements/`. Commands: `cargo test --release -p gremlin-cuda --features cuda` and `cargo test --release -p gremlin-cli --features cuda --test cuda`. The manual CUDA workflow requires a self-hosted `gremlin-cuda` runner; registering that CI runner is a deployment task. Without one the workflow is unexecuted, not a passing GPU gate. The measurements above were run directly over SSH on the supplied GPU machine.
